# [알고리즘] 백트래킹 (Back Tracking)

재귀로 모든 경우의 수를 훑는 문제를 풀다 보면, 어느 순간부터는 `dfs()`를 호출하는 것만으로는 부족해진다.

이미 답이 될 수 없는 길까지 끝까지 내려가면 경우의 수가 너무 빨리 불어나기 때문이다.

이때 쓰는 방법이 백트래킹(Backtracking) 이다.

이번에는 N-Queen과 부분집합의 합을 예시로, 백트래킹이 왜 필요한지 Python 기준으로 정리해 봤다.

## 1. 백트래킹, DFS랑 뭐가 다른 걸까?

백트래킹은 여러 선택지 중 하나를 고르고, 그 선택 뒤에 다시 새로운 선택지를 고르는 과정을 반복한다.

끝까지 갔는데 답이 아니면 최근의 선택으로 돌아와 다른 길을 고른다.

이름 그대로 뒤로 돌아가며 탐색하는 방법이다.

여기서 자주 헷갈리는 부분이 있다.

백트래킹은 보통 DFS 방식으로 구현하지만, DFS 자체와 완전히 같은 말은 아니다.

| 구분 | 일반적인 DFS 완전탐색 | 백트래킹 |
| --- | --- | --- |
| 탐색 방식 | 한 경로를 끝까지 내려간다 | 한 경로를 끝까지 내려간다 |
| 중간 판단 | 일단 끝까지 가 보는 경우가 많다 | 답이 불가능해지는 즉시 멈춘다 |
| 핵심 | 모든 경우를 확인 | 가능성 없는 가지를 미리 자르기 |

쉽게 말해 DFS가 트리를 내려가는 방법이라면,

백트래킹은 내려가다가 “이 길은 아니다” 싶을 때 빨리 접는 규칙에 가깝다.

## 2. 선택지를 트리로 보면 훨씬 쉽다

백트래킹 문제는 눈에 보이지 않는 상태 공간 트리를 떠올리면 편하다.

루트는 아무것도 선택하지 않은 상태이고, 한 번 선택할 때마다 자식 노드가 생긴다.

루트에서 리프 노드까지 내려간 한 경로가 하나의 답 후보가 된다.

예를 들어 4개의 선택지 중 하나를 네 번 고른다면, 첫 번째 선택에 4개, 그 아래에도 4개씩 가지가 뻗는다.

처음에는 전부 가능해 보이지만, 중간에 조건을 깨는 순간이 온다. 그 노드 아래에 있는 자식들은 볼 필요조차 없다.

이 판단을 **유망성 검사(promising)** 라고 한다.

현재까지 고른 내용으로도 나중에 답을 만들 여지가 있으면 유망하고, 없으면 유망하지 않다.

유망하지 않은 노드와 그 아래 경로를 통째로 건너뛰는 작업이 **가지치기(pruning)** 다.

나뭇가지 하나를 자르면 그 밑의 잔가지를 모두 안 봐도 되는 셈이다.

## 3. 재귀 함수 안에서는 무슨 일이 벌어질까?

백트래킹의 뼈대는 생각보다 단순하다. **종료 조건, 후보 선택, 유망성 검사, 원상 복구**만 잡으면 된다.

```python
def dfs(depth):
    if depth == end:
        # 답 처리
        return

    for candidate in candidates:
        if not promising(candidate):
            continue

        choose(candidate)
        dfs(depth + 1)
        undo(candidate)
```

여기서 `return`은 전체 프로그램을 끝낸다는 뜻이 아니다.

지금 호출한 `dfs()` 한 번을 끝내고 부모 호출로 돌아간다는 뜻이다.

부모의 for문은 그다음 후보를 계속 확인한다. 그래서 막다른 길에서 빠져나와 다른 선택지를 시도할 수 있다.

- 후보 하나만 탈락시키고 싶다면 `continue`
- 지금 상태 자체가 답이 될 수 없다면 `return`
- `path.append()`처럼 리스트를 직접 바꿨다면, 재귀 호출 뒤 `path.pop()`으로 반드시 되돌려야 한다.

이 복구를 빼먹으면 이전 가지의 선택이 다음 가지까지 남는다.

## 4. N-Queen, 왜 백트래킹의 대표 문제가 됐을까?

> [프로그래머스](https://school.programmers.co.kr/learn/courses/30/lessons/12952)  
> SW개발자를 위한 평가, 교육의 Total Solution을 제공하는 개발자 성장을 위한 베이스캠프  
> programmers.co.kr

N-Queen은 N×N 체스판에 퀸 N개를 놓되, 어떤 두 퀸도 서로 공격하지 못하게 배치하는 문제다.

퀸은 가로, 세로, 대각선으로 움직인다.

그래서 같은 행, 같은 열, 같은 대각선에 퀸이 있으면 안 된다.

8-Queen을 아무 생각 없이 놓는다면 64칸 중 8칸을 고르는 후보만 64C8 = 4,426,165,368개다.

그런데 실제 해는 92개뿐이다. 답이 아닌 배치를 끝까지 확인하는 방식으로는 너무 많은 시간을 쓴다.

여기서 각 행에는 퀸을 딱 하나만 둔다고 정하면, 재귀 깊이 자체가 행 번호가 된다.

한 행에서 고민할 것은 “어느 열에 놓을까?” 하나뿐이다.

같은 행 충돌은 아예 만들지 않으니 검사할 필요도 없어진다.

현재 행이 row, 놓으려는 열이 col이라면 이전 퀸과 비교할 조건은 두 가지다.

```python
# 같은 열
col == prev_col

# 같은 대각선
abs(col - prev_col) == row - prev_row
```

두 좌표의 행 차이와 열 차이가 같으면 대각선 위에 있다는 뜻이다.

쉽게 말해 대각선으로 한 칸 내려갈 때 열도 한 칸씩 옮겨지는 성질을 이용한 것이다.

## 5. Python으로 N-Queen 세어 보기

`queens[row] = col`로 두면, row번 행의 퀸이 어느 열에 있는지 저장할 수 있다.

2차원 체스판을 직접 만들지 않아도 되어서 코드가 조금 더 단순해진다.

```python
def count_n_queens(n):
    queens = [-1] * n
    count = 0

    def is_safe(row, col):
        for prev_row in range(row):
            prev_col = queens[prev_row]

            if col == prev_col:
                return False

            if abs(col - prev_col) == row - prev_row:
                return False

        return True

    def dfs(row):
        nonlocal count

        if row == n:
            count += 1
            return

        for col in range(n):
            if not is_safe(row, col):
                continue

            queens[row] = col
            dfs(row + 1)
            queens[row] = -1

    dfs(0)
    return count


print(count_n_queens(4))  # 2
```

어떤 열도 가능하지 않으면 그 호출은 끝나고 바로 이전 행으로 돌아간다.

같은 행에 퀸을 두지 않는 DFS만 해도 중복은 줄어든다.

여기에 열과 대각선 충돌을 바로 검사하면 탐색 노드를 훨씬 더 줄일 수 있다.

다만 백트래킹도 만능은 아니다. 가지치기 조건이 약하면 최악의 경우 여전히 지수 시간이 걸린다.

## 6. 부분집합의 합은 ‘넣을까, 말까’로 시작한다

부분집합 합 문제는 각 원소를 선택할지, 선택하지 않을지 결정하는 문제다.

원소가 N개라면 매 원소마다 선택과 미선택 두 갈래가 생기므로, 전체 부분집합 수는 2ⁿ개가 된다.

예를 들어 {-7, -3, -2, 5, 8}에서 합이 0인 부분집합을 찾는다면 {-3, -2, 5}가 답이다.

이때는 음수가 섞여 있다는 점을 조심해야 한다. 현재 합이 목표보다 커졌더라도, 뒤에서 음수를 고르면 다시 내려올 수 있다.

반대로 모든 수가 자연수이고 목표가 21이라면 이야기가 쉬워진다.

{5, 21, 11, 16, 6, 10}에서 {5, 6, 10}처럼 합이 21이 되는 부분집합을 찾을 수 있다. 이 예시에는 답이 총 4개 나온다.

현재 합이 이미 21을 넘었다면 뒤에 양수를 더해도 작아지지 않는다. 이 순간이 바로 가지치기를 할 수 있는 지점이다.

```python
def count_subset_sum(nums, target):
    count = 0

    def dfs(idx, total):
        nonlocal count

        # nums가 모두 양수일 때만 안전한 가지치기다.
        if total > target:
            return

        if idx == len(nums):
            if total == target:
                count += 1
            return

        # nums[idx]를 고르는 경우
        dfs(idx + 1, total + nums[idx])

        # nums[idx]를 고르지 않는 경우
        dfs(idx + 1, total)

    dfs(0, 0)
    return count


nums = [5, 21, 11, 16, 6, 10]
print(count_subset_sum(nums, 21))  # 4
```

이 코드에서 재귀 깊이 `idx`는 “몇 번째 수까지 결정했는가”를 뜻한다.

각 깊이마다 선택 / 미선택 두 갈래로 내려간다.

음수가 포함된 문제라면 `total > target`만으로 자르면 안 된다.

가지치기는 항상 “앞으로 어떤 선택을 해도 답이 될 수 없는가?”를 기준으로 만들어야 한다.

## 7. 백트래킹 문제를 만나면 먼저 이 다섯 가지를 적어 보자

코드를 바로 쓰기보다 아래 다섯 질문에 답하면 재귀 함수의 모양이 훨씬 선명해진다.

- 재귀 깊이는 무엇인가?
- 한 깊이에서 가능한 후보는 무엇인가?
- 지금까지 고른 내용을 어디에 저장할까?
- 어느 순간부터 답이 불가능해지는가?
- 재귀 호출 뒤에 되돌릴 값은 무엇인가?

백트래킹은 모든 경우의 수를 포기하는 방법이 아니다. 모든 경우 중에서 답이 될 가능성이 남아 있는 길만 끝까지 보는 방법이다.

문제를 풀다가 재귀가 끝없이 복잡해 보인다면,

먼저 상태 공간 트리에서 한 칸을 내려갈 때 무엇을 선택하는지부터 그려 보면 된다!!

그 다음에는 “이 길이 이미 틀렸다고 확실히 말할 수 있는 순간이 언제인가”만 찾으면 된다.
