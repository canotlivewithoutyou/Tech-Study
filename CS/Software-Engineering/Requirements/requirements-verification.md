# 요구사항 검증 (Requirements Verification)

## 1. 요구사항 검증이란?

요구사항 검증은 실제로 고객이 원하는 시스템을 제대로 정의했는지 점검하는 과정이다.

검증이 중요한 이유:

- 잘못된 요구사항을 개발 단계까지 가져가면 수정 비용이 매우 커질 수 있음
- 요구사항이 실제 사용자 요구를 반영하고 있는지 확인해야 함
- 문서 내부 요구사항끼리 서로 모순되지 않는지 확인해야 함

---

## 2. 요구사항 검증 방법

### 2.1 동료 검토 (Peer Review)

- 요구사항 명세서 작성자가
- 다른 이해관계자 또는 동료에게 내용을 설명하고
- 결함을 검토받는 방식

### 2.2 워크스루 (Walkthrough)

- 요구사항 명세서를 **미리 배포**
- 검토자들이 사전에 내용을 확인
- 짧은 검토 회의를 통해 오류 및 문제점 확인

### 2.3 인스펙션 (Inspection)

- 작성자를 제외한 다른 전문가 또는 검토자가
- 요구사항 문서를 공식적으로 검토
- 결함을 찾아내는 체계적인 검토 방식

---

## 3. 검증 체크리스트

요구사항을 검증할 때 다음 항목을 확인한다.

| 항목 | 확인 내용 |
|---|---|
| **기능성(Functionality)** | 요구되는 기능이 정확히 정의되었는가 |
| **완전성(Completeness)** | 필요한 요구사항이 빠짐없이 포함되었는가 |
| **일관성(Consistency)** | 요구사항끼리 서로 충돌하거나 모순되지 않는가 |
| **명확성(Unambiguity)** | 하나의 의미로 명확하게 해석되는가 |
| **검증 가능성(Verifiability)** | 테스트나 검토를 통해 검증할 수 있는가 |
| **추적 가능성(Traceability)** | 요구사항의 출처와 변경 이력을 추적할 수 있는가 |
| **변경 용이성(Easily Changeable)** | 요구사항 변경 시 쉽게 수정할 수 있는가 |

---

## 4. 동료 검토 / 워크스루 / 인스펙션 비교

| 구분 | 핵심 특징 |
|---|---|
| **동료 검토** | 작성자가 직접 설명하며 동료와 검토 |
| **워크스루** | 사전 배포 후 짧은 회의 중심 |
| **인스펙션** | 작성자를 제외한 전문가가 공식적으로 검토 |
