# 화이트박스 테스트 (White Box Test)

## 1. 개념

화이트박스 테스트는 프로그램 내부 구조와 논리적 경로를 직접 확인하면서 테스트하는 방식이다.

- 모듈 내부의 내용과 동작을 확인할 수 있음
- 내부의 **논리적인 모든 경로**를 테스트
- 소스 코드의 모든 문장을 최소 한 번 이상 수행하도록 테스트
- 테스트 데이터 선정 기준으로 **검증 기준 / 커버리지(Coverage)** 를 사용

---

## 2. 화이트박스 테스트 검증 기준

### 2.1 구문(문장) 커버리지 — Statement Coverage

- 프로그램 내 **모든 명령문**이 적어도 한 번 이상 수행되도록 테스트

```text
핵심: 모든 문장을 한 번 이상 실행했는가?
```

### 2.2 결정(분기) 커버리지 — Branch Coverage

- 프로그램 내 **전체 결정문의 분기**가 적어도 한 번씩 실행되도록 테스트
- 즉, 각 결정문의 **참(True) / 거짓(False)** 결과를 모두 수행

```text
if (x > 0):
    ...
else:
    ...
```

위와 같은 경우 `x > 0`이 참인 경우와 거짓인 경우를 모두 테스트한다.

### 2.3 조건 커버리지 — Condition Coverage

- 결정문 내부의 **각 개별 조건식**이
  - 적어도 한 번은 참
  - 적어도 한 번은 거짓
- 이 되도록 테스트

예:

```text
if (A && B):
```

- A → True/False 모두 확인
- B → True/False 모두 확인

> 전체 결정 결과보다 **개별 조건식 자체**에 초점을 둔다.

### 2.4 조건/결정 커버리지 — Condition/Decision Coverage

- **전체 조건식의 참/거짓 결과**
- **개별 조건식의 참/거짓 결과**

를 모두 만족하도록 테스트한다.

즉, **결정 커버리지 + 조건 커버리지**를 함께 만족한다.

### 2.5 변경 조건/결정 커버리지 — MC/DC

**Modified Condition/Decision Coverage**

- 각 개별 조건식이 **독립적으로 전체 결정 결과에 영향을 미치는지** 확인
- 복합 조건식에서 한 조건만 변경했을 때 전체 결정 결과가 달라지는 경우를 확인

예:

```text
A && B
```

A의 값만 바꾸었을 때 결과가 달라지는 경우와  
B의 값만 바꾸었을 때 결과가 달라지는 경우를 각각 확인한다.

### 2.6 다중 조건 커버리지 — Multiple Condition Coverage

- 결정문 내 모든 개별 조건식의 **가능한 모든 논리적 조합**을 테스트
- 100% 커버리지를 목표로 함

예:

```text
A && B
```

가능한 조합:

```text
A=T, B=T
A=T, B=F
A=F, B=T
A=F, B=F
```

---

## 3. 커버리지 비교

| 커버리지 | 확인 대상 |
|---|---|
| **구문 커버리지** | 모든 명령문 |
| **결정 커버리지** | 전체 결정문의 참/거짓 |
| **조건 커버리지** | 각 개별 조건의 참/거짓 |
| **조건/결정 커버리지** | 결정 + 개별 조건 모두 |
| **MC/DC** | 개별 조건이 독립적으로 결정 결과에 미치는 영향 |
| **다중 조건 커버리지** | 모든 조건 조합 |

## 4. 화이트박스 테스트 종류

### 4.1 기초 경로 검사 (Base Path Testing)

- 대표적인 화이트박스 테스트 기법
- **동적 테스트**
- 테스트 케이스 설계자가 절차적 설계의 논리적 복잡성을 측정할 수 있도록 하는 기법
- 측정 결과는 실행 경로의 기초를 정의하는 지침으로 사용

### 4.2 제어 구조 검사 (Control Structure Testing)

프로그램의 제어 구조를 중심으로 검사한다.

#### 조건 검사

- 프로그램 모듈 내부의 **논리적 조건**을 테스트

#### 루프 검사

- 프로그램의 **반복(Loop) 구조**를 테스트

#### 자료 흐름 검사

- 변수의 정의와 사용 위치를 중심으로 테스트
