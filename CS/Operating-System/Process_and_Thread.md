# 프로세스와 스레드 (Process & Thread)

## 1. 프로세스 (Process)

- **CPU에 의해 처리되는 실행 중인 프로그램**
- 프로세스 제어 블록(**PCB, Process Control Block**)에 프로세스 식별자(PID), 상태, 프로그램 카운터, 레지스터 정보 등 중요한 정보를 저장한다.
- 프로세스 생성 시 고유한 PCB가 만들어지고, 종료되면 운영체제가 PCB를 제거한다.

### 프로세스 상태와 전이

```text
제출(Submit) → 접수(Hold) → 준비(Ready) ⇄ 실행(Run) → 종료(Terminated)
                 ↕                ↑          ↓
              디스크             대기(Wait / Block)
```

| 전이                              | 의미                                                                                   |
| --------------------------------- | -------------------------------------------------------------------------------------- |
| **Dispatch**                      | 준비 상태의 프로세스가 CPU를 할당받아 **실행 상태**로 전이                             |
| **Time Run Out**                  | 할당 시간이 끝나 실행 → 준비 상태로 전이                                               |
| **Wait / Block**                  | 입출력 요청 등으로 실행 → 대기 상태로 전이                                             |
| **Wake Up**                       | 입출력 완료 등으로 대기 → 준비 상태로 전이                                             |
| **Context Switching (문맥 교환)** | 현재 프로세스의 실행 문맥(레지스터 등)을 저장하고 다음 프로세스의 문맥을 복원하는 과정 |

> **주의:** 문맥 교환은 일반적으로 디스패치 및 CPU 교체 과정에서 발생하며, 상태 전이 이름 그 자체는 아니다.

## 2. 스레드 (Thread)

- **프로세스 내 작업·실행 단위**
- **단일 스레드**: 프로세스에 스레드가 하나 있다.
- **다중 스레드**: 한 프로세스에 여러 스레드가 있다.
- 동일 프로세스 내부의 스레드는 코드·데이터·힙 등의 자원을 공유하지만, 각자 스택과 레지스터 실행 문맥을 가진다.

### 다중 스레드의 장점

- 작업 병행을 통해 **응답성 향상**
- 같은 프로세스의 자원 공유를 통한 **메모리 사용 효율 향상**
- 독립적인 프로세스를 생성하는 것에 비해 생성·전환 비용을 줄일 수 있음
- 다중 코어 환경에서 **병렬 처리** 가능

### 사용자 수준과 커널 수준 스레드

| 구분            | 특징                                                                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **사용자 수준** | 사용자 공간의 라이브러리에서 관리. 커널 개입이 적어 관리가 빠를 수 있으나, 구현과 매핑 방식에 따라 한 스레드의 블로킹이 전체에 영향을 줄 수 있음 |
| **커널 수준**   | 운영체제 커널이 관리·스케줄링. 커널 관리 오버헤드가 있지만 블로킹 및 다중 코어 실행 관리에 유리                                                  |

## 실기 암기 포인트

- PCB = **프로세스 관리 정보**
- Dispatch = **준비 → 실행**
- Wake Up = **대기 → 준비**
- Context Switching = **기존 문맥 저장 + 다음 문맥 복원**
- Thread = **프로세스 내부 실행 단위**
